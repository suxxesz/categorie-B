# Решение — отчёт по авансам и остаткам

Программа читает выгрузку из `data/` и строит отчёт **на дату**: по каждой работе —
цена, выплачено, остаток; по каждому договору — итоги.

- Язык: **TypeScript** (Node.js).
- Деньги считаются **целыми копейками** (`bigint`) — без float, до копейки.
- Ни БД, ни Docker, ни интерфейса — один скрипт.

## Запуск

```bash
cd solution
npm install

# отчёт на контрольную дату 10.11.2026
npx tsx report.ts --date 2026-11-10

# или через npm-скрипт
npm run report
```

Параметры:

| Флаг | Значение | По умолчанию |
|------|----------|--------------|
| `--date YYYY-MM-DD` | дата, на которую строим отчёт | `2026-11-10` |
| `--csv <путь>` | дополнительно выгрузить отчёт в CSV | нет |

Пример с выгрузкой в файл:

```bash
npx tsx report.ts --date 2026-11-10 --csv report.csv
```

## Что внутри

- `report.ts` — вся логика: разбор CSV, расчёт «на дату», разнесение платежей, вывод.
- `package.json`, `tsconfig.json` — запуск через `tsx`, строгий TypeScript.

Весь расчёт — на `bigint`-копейках. Единственное деление на 100 — только при печати
сумм (расчёт к этому моменту уже завершён в целых копейках).

## Логика кратко

1. **На дату.** Платёж учитывается, если `paid_at ≤ дата`; возврат — если `refunded_at ≤ дата`;
   `queued` и будущие платежи идут в строку «в очереди».
2. **Статус работы** восстанавливается по датам приёмки/отмены, а не берётся из выгрузки.
3. **Разнесение** непривязанных платежей — водопадом по принятым работам; непокрытый остаток
   показывается как «аванс, не закрытый работами».
4. Отменённые работы в остаток не входят.

Подробно и с альтернативами — в [`../DECISIONS.md`](../DECISIONS.md).
Как читать отчёт бухгалтеру — в [`../NOTE_FOR_ACCOUNTANT.md`](../NOTE_FOR_ACCOUNTANT.md).
